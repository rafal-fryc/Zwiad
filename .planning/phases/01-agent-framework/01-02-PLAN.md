Create JSON Schema files and parallel jq expression files in `pipeline/schemas/`.

**envelope.schema.json** — Per D-07, common envelope with these required fields:
```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "Pipeline Handoff Envelope",
  "description": "Common envelope for all inter-agent JSON state files",
  "type": "object",
  "required": ["schema_version", "pipeline_run_id", "timestamp", "stage", "status", "data"],
  "properties": {
    "schema_version": { "type": "string", "const": "1.0" },
    "pipeline_run_id": { "type": "string", "description": "Timestamp-based run ID, e.g. 2026-04-06T14-30-00" },
    "timestamp": { "type": "string", "format": "date-time" },
    "stage": { "type": "string", "enum": ["scanner", "human-review", "researcher", "reviewer", "categorizer"] },
    "status": { "type": "string", "enum": ["complete", "error", "pending-review"] },
    "data": { "type": "object" }
  },
  "additionalProperties": false
}
```

**envelope.jq** — jq expression that returns true if the envelope is valid:
```jq
(.schema_version | type == "string") and
(.pipeline_run_id | type == "string") and
(.timestamp | type == "string") and
(.stage | type == "string") and
(.stage | IN("scanner", "human-review", "researcher", "reviewer", "categorizer")) and
(.status | type == "string") and
(.status | IN("complete", "error", "pending-review")) and
(.data | type == "object")
```

**scanner.schema.json** — Scanner output data schema. The `data` field must contain `findings` array. Each finding has: `id` (string), `title` (string), `source` (string), `source_url` (string), `summary` (string), `relevance` (string, one of "high", "medium", "low"), `jurisdiction` (string), `development_type` (string, one of "legislation", "regulation", "enforcement", "guidance", "court-decision", "other").

**scanner.jq** — Validates scanner stage data:
```jq
(.data.findings | type == "array") and
(.data.findings | length >= 0) and
(.data.findings | all(
  (.id | type == "string") and
  (.title | type == "string") and
  (.source | type == "string") and
  (.source_url | type == "string") and
  (.summary | type == "string") and
  (.relevance | type == "string") and
  (.relevance | IN("high", "medium", "low")) and
  (.jurisdiction | type == "string") and
  (.development_type | type == "string") and
  (.development_type | IN("legislation", "regulation", "enforcement", "guidance", "court-decision", "other"))
))
```

**researcher.schema.json** — Researcher output data schema. The `data` field must contain `reports` array. Each report has: `finding_id` (string, references scanner finding), `report_path` (string, path to markdown report file), `format` (string, one of "client-alert", "research-memo"), `jurisdiction_tags` (array of strings), `confidence_summary` (object with `high` / `medium` / `low` integer counts).

**researcher.jq** — Validates researcher stage data:

```jq
(.data.reports | all(
  (.finding_id | type == "string") and
  (.report_path | type == "string") and
  (.format | type == "string") and
  (.format | IN("client-alert", "research-memo")) and
  (.jurisdiction_tags | type == "array") and
  (.confidence_summary | type == "object") and
  (.confidence_summary.high | type == "number") and
  (.confidence_summary.medium | type == "number") and

```

**reviewer.schema.json** — Reviewer output data schema. The `data` field must contain `reviews` array. Each review has: `finding_id` (string), `report_path` (string), `status` (string, one of "verified", "disputed", "needs-human-review"), `iteration_count` (number, 1-3), `claims_checked` (number), `issues_found` (array of objects with `claim` string, `issue` string, `severity` string one of "critical", "major", "minor").

**reviewer.jq** — Validates reviewer stage data:
```jq
(.data.reviews | type == "array") and
(.data.reviews | all(
  (.finding_id | type == "string") and
  (.report_path | type == "string") and
  (.status | type == "string") and
  (.status | IN("verified", "disputed", "needs-human-review")) and
  (.iteration_count | type == "number") and
  (.iteration_count >= 1) and
  (.iteration_count <= 3) and
  (.claims_checked | type == "number") and
  (.issues_found | type == "array") and
  (.issues_found | all(
    (.claim | type == "string") and

    (.severity | IN("critical", "major", "minor"))
```

Create `pipeline/scripts/validate-handoff.sh` — the bash+jq validation script per D-05.

The script takes two arguments: `<schema-name>` and `<json-file>`.

Script behavior (per D-06, hard fail with error messages):

1. **Usage check**: If fewer than 2 arguments, print usage and exit 1.
2. **File existence check**: If the JSON file does not exist, print "ERROR: File not found: $FILE" to stderr and exit 1.
3. **JSON syntax validation**: Run `jq empty "$FILE"`. If it fails, print "ERROR: Invalid JSON in $FILE" to stderr and exit 1.
4. **Envelope validation**: Run `jq -e -f pipeline/schemas/envelope.jq "$FILE"`. If it fails, print "ERROR: Envelope validation failed for $FILE" with list of required fields to stderr and exit 1.
5. **Schema version check** (per D-08): Extract `schema_version` with `jq -r '.schema_version' "$FILE"` and compare to expected "1.0". If mismatch, print "ERROR: Schema version mismatch in $FILE: expected 1.0, got $ACTUAL" to stderr and exit 1.
6. **Stage-specific validation**: Look for `pipeline/schemas/${SCHEMA}.jq`. If the file exists, run `jq -e -f "pipeline/schemas/${SCHEMA}.jq" "$FILE"`. If it fails, print "ERROR: Stage-specific validation failed for $FILE against $SCHEMA" to stderr and exit 1.
7. **Success**: Print "OK: $FILE validates against $SCHEMA" to stdout and exit 0.

Make the script executable with `chmod +x`.

The script must use `set -euo pipefail` at the top. Use `SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"` to resolve paths relative to the pipeline/ directory (not the working directory), so `pipeline/schemas/` lookups work regardless of where the script is invoked from. The schema path should be `"${SCRIPT_DIR}/schemas/${SCHEMA}.jq"` and the envelope path should be `"${SCRIPT_DIR}/schemas/envelope.jq"`.
