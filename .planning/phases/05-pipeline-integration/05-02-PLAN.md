Create `run_pipeline.py` at project root per D-12. Use only Python 3 stdlib (argparse, subprocess, json, os, sys, pathlib, datetime, time). The script has these components:

**Constants:**
```python
PROJECT_ROOT = Path(__file__).resolve().parent
PIPELINE_DIR = PROJECT_ROOT / "pipeline"
RUNS_DIR = PIPELINE_DIR / "runs"
PENDING_DIR = PIPELINE_DIR / "pending"
```

**Functions:**

1. `create_run_id()` — Returns `datetime.now(timezone.utc).strftime("%Y-%m-%dT%H-%M-%S")` (matches existing run-scanner.sh pattern from line 12).

2. `setup_run_dir(run_id)` — Creates `pipeline/runs/{run_id}/` directory. Returns Path to it.

3. `notify(title, message)` — Calls `notify-send --urgency=normal "Zwiad: {title}" "{message}"` via subprocess with timeout=5. Catch and ignore FileNotFoundError and TimeoutExpired (non-critical per D-09). Also print the notification to stdout as fallback.

4. `run_stage(name, cmd, run_dir, audit_entries)` — Helper that:
   - Records start time
   - Runs `subprocess.run(cmd, capture_output=True, text=True, cwd=str(PROJECT_ROOT))` 
   - Records end time, calculates duration
   - Checks returncode; if nonzero: logs error to `run_dir/error.log`, appends error to audit_entries, calls `notify("Pipeline Failure", f"Stage {name} failed for run {run_id}")`, raises RuntimeError
   - Appends stage summary dict to audit_entries: `{"name": name, "duration_seconds": duration, "stdout_tail": last 20 lines of stdout, "status": "complete"}`
   - Returns the CompletedProcess

5. `run_scan_phase(run_id, run_dir, input_file=None, web_only=False)` — Per D-08, D-14, D-15:
   - Build orchestrator prompt: `"Scan phase for run {run_id}. Write all output to pipeline/runs/{run_id}/."` Add input file path or web-only flag to prompt.
   - Call `run_stage("orchestrator-scan", ["claude", "-p", "--agent", "orchestrator", "--output-format", "json", "--max-turns", "30", prompt], run_dir, audit_entries)`
   - Check for `scan-complete.marker` in run_dir
   - Notify: `notify("Findings Ready", f"Run {run_id}: Review scanner findings at pipeline/runs/{run_id}/scanner-review.md")`
   - Return audit_entries

6. `run_research_phase(run_id, run_dir)` — Per D-10, D-14:
   - Validate state: `scanner-approved.json` must exist (error if not)
   - Check `categorizer-output.json` does not already exist (error: "Run already complete")
   - Build orchestrator prompt: `"Research phase for run {run_id}. Process approved findings from pipeline/runs/{run_id}/scanner-approved.json."`
   - Call `run_stage("orchestrator-research", ["claude", "-p", "--agent", "orchestrator", "--output-format", "json", "--max-turns", "50", prompt], run_dir, audit_entries)` (higher max-turns for multi-finding processing)
   - Check for `pipeline-complete.marker` or `has-escalations.marker`
   - If escalations: notify("Escalations Pending", f"Run {run_id}: Review escalations")
   - If complete: notify("Pipeline Complete", f"Run {run_id}: Reports filed")
   - Return audit_entries

7. `write_audit_log(run_id, run_dir, audit_entries, overall_status)` — Per D-05, D-06, D-07. Writes `run_dir/audit-log.md` with this template:
```markdown
# Pipeline Audit Log

**Run ID:** {run_id}
**Started:** {start_timestamp}
**Completed:** {end_timestamp}
**Status:** {overall_status}

{for each entry in audit_entries:}
## {entry.name}
- **Duration:** {formatted duration}
- **Status:** {entry.status}
{if entry has details: list them}
{if entry has error: show error message}

## Errors
{list errors or "None"}
```
   The audit log lists stage names and outcomes but not full content (per D-06: "compact and scannable"). Read the run directory JSON files to extract counts:
   - From scanner-output.json: findings count, source_failures count
   - From scanner-approved.json (if exists): approved count
   - From reviewer-output.json (if exists): verified/escalated counts
   - From categorizer-output.json (if exists): filed/pending counts

8. `cmd_run(args)` — Handler for `run` subcommand per D-15:
   - Validate: either `args.input` or `args.web_only` must be set
   - If `args.input`: verify file exists, determine if .eml or .html
   - Create run_id and run_dir
   - Call run_scan_phase with appropriate flags
   - Write audit log (partial — scan phase only)
   - Print: "Scan complete. Review findings at: pipeline/runs/{run_id}/scanner-review.md"
   - Print: "After approval, run: python3 run_pipeline.py resume {run_id}"

9. `cmd_resume(args)` — Handler for `resume` subcommand per D-10:
   - Validate run_id exists as directory
   - Call run_research_phase
   - Write/append audit log (research phase entries)
   - Print summary

10. `main()` — argparse setup:
    - Parser with description "Zwiad regulatory monitoring pipeline"
    - Subparsers for `run` and `resume`
    - `run` subparser: `--input` (path to digest file), `--web-only` (flag, action=store_true). Add validation: at least one must be provided.
    - `resume` subparser: `run_id` positional argument
    - Parse and dispatch

**Error handling per D-11:**
- Wrap each phase in try/except
- On exception: write error to `run_dir/error.log`, write audit log with status "error", call notify("Pipeline Failure", error message), exit with code 1
- No automatic retry

**Cron compatibility:**
- Script uses absolute paths derived from `PROJECT_ROOT`
- All subprocess calls use `cwd=str(PROJECT_ROOT)`
- Stdout/stderr output for cron log capture
- Print environment info at startup (PATH, DISPLAY) for cron debugging

Also create `pipeline/pending/.gitkeep` (empty file) to ensure the pending directory is tracked in git per D-03.

Make `run_pipeline.py` executable: add `#!/usr/bin/env python3` shebang.
